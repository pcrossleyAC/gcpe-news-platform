# Hardening Batch 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Five small hardening fixes. NRMS upload names move out of URLs. A tick step sweeps orphaned Calendar attachment bytes. Keyboard focus survives saving in staff-web. One shared test-site rule replaces four copies. `npm run test:clean-dbs` drops leftover test databases.

**Architecture:** Each fix stays inside the package that owns it. NRMS gets an `X-GCPE-File-Name` middleware like the Calendar's. The Calendar gets a bounded, cursor-driven sweeper exposed as a worker and run by `/stack/tick`. Staff-web swaps in-flight `isDisabled` for react-aria's `isPending` (buttons) or `isReadOnly` (fields, switches), with a static guard test. `@gcpe/config` gains `isTestSite`/`isRealProduction`. A root script cleans up test databases.

**Tech Stack:** Node 24, TypeScript, Express 5, zod 3, drizzle-orm, Postgres, React 19 + `@bcgov/design-system-react-components` 0.8.1 (react-aria-components), Vitest 4, tsx.

**Spec:** Paul's approved scope for this batch, restated under **Scope** below. It builds on `docs/superpowers/plans/phase-5-carry-forward.md` "Platform hardening", as it stood at HEAD `ab1e5f7`. This commit deletes the two items this plan takes from that file; the text is quoted under Scope. Read both.

## Scope (as approved)

1. **NRMS upload names out of URLs.** apps/nrms's site-files and page-images upload routes still take the file name in `?name=`, so it lands in proxy access logs. Move it to the `X-GCPE-File-Name` header, as the Calendar's upload route did (`apps/calendar/src/http/file-routes.ts`). Update staff-web's callers. Rule on whether `?name=` stays accepted for one release. Add tests showing the name never appears in a URL.
2. **Sweeper for orphaned Calendar attachment bytes.** When an attachment is replaced or removed, a failed object-store delete after the DB commit leaves the bytes behind. Today this is only logged, by activity id and file id (`deleteQuietly` in `apps/calendar/src/activities/files.ts`). Rule on tick or CLI. The sweeper must be safe against an in-flight upload, work in bounded batches, and never delete bytes a row still references.
3. **Keyboard focus in staff-web.** Controls that use `isDisabled={busy}` while saving drop keyboard focus to `<body>`. Find every instance, apply the `isPending` fix from 6d–6e (`SimilarReleasesPanel.tsx`), and add a test pattern that catches a regression.
4. **One shared test-site rule** in `@gcpe/config`, used everywhere. Behaviour stays byte-identical, pinned by tests. No new heavy dependencies.
5. **`npm run test:clean-dbs`.** Use only the strict patterns `^test_[0-9a-f]{20}$` and `^test_nr_[0-9a-f]{16}$` for databases and `^nr_[0-9a-f]{16}$` for roles. Skip databases with active connections. Dry run by default; `--confirm` drops. Never touch any other database.

Folded in (tiny Phase 4 low-priority notes): `PreferencesError` gets a `name` and a test for empty `subscribedCategories`. db-kit's `runMigrations` gets a pointer comment on drizzle's `folderMillis` skip.

## Rulings (planner's, against the code at HEAD `ab1e5f7`)

1. **`?name=` is refused immediately, with no compatibility window.** Every caller is in this repo and ships in the same deploy: staff-web, `tests/e2e/playwright-support.ts`, `scripts/siteground-website-walkthrough.sh`, and `apps/stack/src/stack.test.ts`. NRMS's upload routes are not a public API. The only casualty is a staff-web tab left open across a deploy: its next upload gets a 400 ("Name the file.") until it reloads. The three upload query schemas become `.strict()`, so a stray `name` in the query is a 400 even when the header is present, and a forgotten caller fails loudly.
2. **The fix covers three NRMS upload routes, not two.** `POST /releases/:id/files` (`fileQuerySchema` in `apps/nrms/src/http/media-routes.ts`) carries the same `?name=` leak, for embargoed release translations. It is the same router and the same fix, so it is included. For page images, only `name` moves. `altEn`, `altFr` and `sortOrder` stay in the query because alt text is public page content.
3. **The NRMS header middleware is a small NRMS-local module** (`apps/nrms/src/http/file-name.ts`), not a shared package. Apps never import each other's `src`, and it is about 20 lines. Each route keeps its existing name validation unchanged; only the transport moves.
4. **The sweeper runs on the tick, not as a CLI.** Only the stack bundle ships to boxs.ca (`scripts/build-siteground.mjs` bundles `apps/stack/src/main.ts` alone), so a CLI could never reach the store's files there, and orphans would never be cleaned. It is a Calendar worker, `orphanSweep`, run as the tick step `calendar.orphan-sweep` right after `calendar.lock-sweep`. A standalone Calendar also runs it every 60 s in `startLoops`, like `lockSweep`.
5. **Sweeper safety.** Three guards:
   - It deletes only objects at least 24 h old by the object's own `updatedAt`. An in-flight upload stores bytes before its row commits, and its key is always new and random (`randomFileKey`), so fresh bytes are never touched.
   - It lists objects before reading any rows, so a row committed before the read is always seen.
   - Before deleting, it re-checks every candidate key against **all** `activity_files` rows, not just that activity's.

   It walks activities by id in keyset batches of 200 per call (`store.list("activities/<id>")`, verified at HEAD to list only that folder: `activities/123` does not pick up `activities/1234`). It deletes at most 50 objects per call. The cursor lives in memory and wraps to the start after the last activity. With about 50,000 activities and a one-minute tick, a full pass takes about 4 h. A process restart starts the pass again from the beginning. No migration is needed.
6. **Focus fix: every in-flight flag, not about 15.** At HEAD, 127 staff-web controls use an in-flight flag in `isDisabled` (118 match `busy|saving|submitting|loading|pending`; 9 more use `creating|deleting|sending|retrying` or `MediaHubSearch`'s `disabled` prop). The rule:
   - **Button:** the in-flight part moves to `isPending`. Any other condition stays in `isDisabled`.
   - **TextField and Switch:** the in-flight part moves to `isReadOnly`, which stays focusable.
   - Native `<input disabled>` elements are out of scope.
   - `MediaHubSearch`'s `disabled` prop is renamed `busy` and becomes `isPending`.
7. **Focus regression pattern: a static guard plus a behavioural test.** `tests/staff-web-focus-guard.test.ts` fails on any staff-web `isDisabled={…}` that names an in-flight flag. Behavioural tests assert the property that keeps focus in a real browser: no `disabled` attribute while pending (`aria-disabled="true"` for buttons, `readonly` for fields). Asserting `document.activeElement` alone would pass in jsdom even with the old code, because jsdom does not move focus off a disabled element.
8. **The shared rule lives in `packages/config/src/test-site.ts`.** It has no imports and is exported from `@gcpe/config` as `isTestSite(env)` and `isRealProduction(env)`. `@gcpe/embeddings` gains a dependency on `@gcpe/config`, a workspace package whose dependencies (`@gcpe/http-kit`, `zod`) embeddings already has. Nothing in the browser needs the rule: staff-web reads `isTestSite` from `GET /nrms/api/config`. The five copies replaced are:
   - embeddings' `isRealProduction`;
   - Core's inline `testDeployment`;
   - public-site's `isTestSite`;
   - NRMS's `nrmsIsTestSite`;
   - the stack's `usesFakeEntra`.
9. **Narrower guards stay as they are.** `usesFakeMediaHub`, `usesFakeEmergencyFeed` and `usesFakeFlickr` (in `apps/stack/src/env.ts`) and `@gcpe/auth`'s local-admin guard ignore `SITE_ENVIRONMENT`. That is a different, stricter rule, and byte-identical behaviour forbids widening them. Raised as Q92.
10. **`test:clean-dbs` also skips databases created less than 60 minutes ago** (`--min-age-minutes`), by the age of the database's `PG_VERSION` file. Parallel worktrees run suites against the same local Postgres. Their pools close idle connections after 10 s, so a database can have no session mid-suite. This was confirmed while planning: 4 harness databases appeared and vanished within minutes.
11. **`test:clean-dbs` drops with plain `DROP DATABASE`, never `WITH (FORCE)`.** Verified on Postgres 14 at HEAD: a database with a live session is refused with SQLSTATE 55006 after Postgres waits up to 5 s. The script reports that as "in use". Roles are dropped after databases, and only when their `test_nr_` twin no longer exists and they have no session; a role that still owns objects (2BP01) is reported, not forced. `test_tzcheck_…`, `migrate_…` and `leak_…` databases are left alone, as approved (Q93).
12. **Carry-forward cleanup is in this plan commit.** Per each file's own rule, the items are deleted when the plan that takes them is written:
    - from `phase-5-carry-forward.md`: the orphan sweeper and NRMS `?name=` bullets;
    - from `phase-4-carry-forward.md`: the `PreferencesError` and `folderMillis` bullets.

    The Phase 2 `as_it_happens` note stays (it is information, not work), and so does the Phase 4 exit ops-docs item (not tiny). Q92–Q95 are added to `docs/parity/open-questions.md` in the same commit.

```ts
/** The three shared, unprefixed stack variables the rule reads. `process.env` fits this shape. */
export interface TestSiteEnv {
  NODE_ENV?: string | undefined;
  LOCAL_ADMIN_ALLOW_IN_PRODUCTION?: string | undefined;
  SITE_ENVIRONMENT?: string | undefined;
}

/**
 * The platform's one test-site rule. A deployment is a test site unless it is the real
 * production deployment: NODE_ENV isn't "production", or it is but the deployment is marked as a
 * test site anyway, by LOCAL_ADMIN_ALLOW_IN_PRODUCTION=true (boxs.ca) or SITE_ENVIRONMENT=test.
 * No imports, so any package can use it.
 */
export function isTestSite(env: TestSiteEnv): boolean {
  return env.NODE_ENV !== "production" || env.LOCAL_ADMIN_ALLOW_IN_PRODUCTION === "true" || env.SITE_ENVIRONMENT === "test";
}

/** The real production deployment: not a test site. */
export function isRealProduction(env: TestSiteEnv): boolean {
  return !isTestSite(env);
}
```

```ts
/**
 * Reads the upload's name from {@link FILE_NAME_HEADER} before any body is read, validated by the
 * route's own `schema`, into `res.locals.fileName`. A missing, empty or undecodable header, or a
 * name the schema refuses, is a 400 in the same shape as any other validation error.
 */
export const fileNameHeader =
  (schema: z.ZodType<string>) =>
  (req: Request, res: Response, next: NextFunction): void => {
    const header = req.header(FILE_NAME_HEADER);
    let decoded: string | undefined;
    if (header) {
      try {
        decoded = decodeURIComponent(header);
      } catch {
        decoded = undefined;
      }
    }
    if (decoded === undefined) return void res.status(400).json({ error: "invalid request", issues: missingName().issues });
    const parsed = z.object({ name: schema }).safeParse({ name: decoded });
    if (!parsed.success) return void res.status(400).json({ error: "invalid request", issues: parsed.error.issues });
    res.locals.fileName = parsed.data.name;
    next();
  };
```

```ts
import { asc, gt, inArray } from "drizzle-orm";
import type { Db } from "@gcpe/db-kit";
import { safeErrorLabel } from "@gcpe/http-kit";
import type { ObjectStore } from "@gcpe/storage";
import { activities, activityFiles } from "../db/schema";

/** Activities whose folders one call lists. */
export const ORPHAN_SWEEP_ACTIVITIES = 200;
/** Objects one call deletes at most. */
export const ORPHAN_SWEEP_MAX_DELETES = 50;
/**
 * Bytes younger than this are never swept. An upload stores its bytes before its row commits,
 * always under a new random key, so a fresh object with no row may be an upload still in flight.
 */
export const ORPHAN_MIN_AGE_MS = 24 * 60 * 60 * 1000;
const KEY_CHECK_CHUNK = 500;

export interface OrphanSweepResult {
  scanned: number;
  deleted: number;
  failed: number;
}

export interface OrphanSweepOptions {
  activities?: number;
  maxDeletes?: number;
  minAgeMs?: number;
  now?: () => Date;
}

/**
 * Finds and deletes attachment bytes no `activity_files` row references: the bytes left behind
 * when a replace or remove committed but the store delete after it failed. Each call walks the
 * next batch of activities by id, from a cursor kept in memory, and wraps to the start after
 * the last one.
 */
export function createOrphanSweeper(db: Db, store: ObjectStore, opts: OrphanSweepOptions = {}): () => Promise<OrphanSweepResult> {
  const size = opts.activities ?? ORPHAN_SWEEP_ACTIVITIES;
  const maxDeletes = opts.maxDeletes ?? ORPHAN_SWEEP_MAX_DELETES;
  const minAgeMs = opts.minAgeMs ?? ORPHAN_MIN_AGE_MS;
  const now = opts.now ?? (() => new Date());
  let after = 0;

  return async () => {
    const ids = (await db.select({ id: activities.id }).from(activities).where(gt(activities.id, after)).orderBy(asc(activities.id)).limit(size)).map((r) => r.id);
    const cutoff = now().getTime() - minAgeMs;

    // List the bytes before reading any row, so a row that committed before the reads below is seen.
    const aged: { activityId: number; key: string }[] = [];
    for (const id of ids) {
      for (const o of await store.list(`activities/${id}`)) if (o.updatedAt.getTime() <= cutoff) aged.push({ activityId: id, key: o.key });
    }

    const referenced = new Set<string>();
    if (ids.length > 0) {
      for (const r of await db.select({ key: activityFiles.storageKey }).from(activityFiles).where(inArray(activityFiles.activityId, ids))) referenced.add(r.key);
    }
    // Any row anywhere keeps its bytes, not only a row on the activity whose folder holds them.
    const unreferenced = aged.filter((o) => !referenced.has(o.key));
    for (let i = 0; i < unreferenced.length; i += KEY_CHECK_CHUNK) {
      const chunk = unreferenced.slice(i, i + KEY_CHECK_CHUNK).map((o) => o.key);
      for (const r of await db.select({ key: activityFiles.storageKey }).from(activityFiles).where(inArray(activityFiles.storageKey, chunk))) referenced.add(r.key);
    }
    const orphans = unreferenced.filter((o) => !referenced.has(o.key));

    let deleted = 0;
    let failed = 0;
    for (const o of orphans.slice(0, maxDeletes)) {
      try {
        if (await store.delete(o.key)) deleted++;
      } catch (e) {
        failed++;
        console.error("[calendar] orphan sweep could not delete a stored file", safeErrorLabel(e));
      }
    }

    if (orphans.length > maxDeletes && deleted > 0) {
      // More orphans than one call may delete: come back to the first activity not finished.
      const i = ids.indexOf(orphans[maxDeletes]!.activityId);
      if (i > 0) after = ids[i - 1]!;
    } else {
      after = ids.length < size ? 0 : ids[ids.length - 1]!;
    }
    return { scanned: ids.length, deleted, failed };
  };
}
```

```ts
const ROOT = fileURLToPath(new URL("..", import.meta.url));
const SRC = join(ROOT, "apps/staff-web/src");
// Names this app gives a request in flight. A control disabled by one loses keyboard focus to
// the page the moment the request starts; use isPending (buttons) or isReadOnly (fields) instead.
const IN_FLIGHT = /\b(busy|saving|submitting|loading|pending|creating|deleting|sending|retrying)\b/;

function inFlightDisables(source: string): { line: number; expr: string }[] {
  const found: { line: number; expr: string }[] = [];
  for (const m of source.matchAll(/isDisabled=\{/g)) {
    let depth = 1;
    let i = m.index + m[0].length;
    const start = i;
    while (depth > 0 && i < source.length) {
      if (source[i] === "{") depth++;
      else if (source[i] === "}") depth--;
      i++;
    }
    const expr = source.slice(start, i - 1);
    if (IN_FLIGHT.test(expr)) found.push({ line: source.slice(0, m.index).split("\n").length, expr: expr.replace(/\s+/g, " ").trim() });
  }
  return found;
}

function sources(dir: string): string[] {
  return readdirSync(dir).flatMap((e) => {
    const p = join(dir, e);
    if (statSync(p).isDirectory()) return sources(p);
    return /\.tsx?$/.test(p) && !/\.test\.tsx?$/.test(p) ? [p] : [];
  });
}

describe("staff-web keeps keyboard focus while a request is in flight", () => {
  it("the scanner flags in-flight flags, across lines, and nothing else", () => {
    expect(inFlightDisables("<Button isDisabled={busy}>")).toHaveLength(1);
    expect(inFlightDisables("<Button isDisabled={\n  index === 0 || section.saving\n}>")).toHaveLength(1);
    expect(inFlightDisables("<Button isDisabled={retrying.has(keyOf(d))}>")).toHaveLength(1);
    expect(inFlightDisables("<Button isDisabled={readOnly || !canEdit}>")).toEqual([]);
    expect(inFlightDisables("<Button isPending={busy} isDisabled={dirty}>")).toEqual([]);
  });

  it("no control is disabled by an in-flight flag", () => {
    const offenders = sources(SRC).flatMap((f) => inFlightDisables(readFileSync(f, "utf8")).map((o) => `${relative(ROOT, f)}:${o.line} isDisabled={${o.expr}}`));
    expect(offenders).toEqual([]);
  });
});
```

```ts
/**
 * `npm run test:clean-dbs [-- --confirm] [-- --min-age-minutes=N]`: drops the databases and roles
 * test runs left behind (a killed run never reaches its own drop), on TEST_DATABASE_ADMIN_URL's
 * server (default postgres://localhost:5432/postgres). Only the names the harness creates:
 * test_<20 hex> (createTestDatabase), test_nr_<16 hex> and its role nr_<16 hex> (the News API's
 * restricted test database). A database with any session, or younger than the minimum age
 * (default 60 minutes: another checkout's suite may be between connections), is skipped. Dry run
 * by default; --confirm to drop. Plain DROP, never FORCE: Postgres itself refuses a database
 * someone connected to in the meantime.
 */
import { realpathSync } from "node:fs";
import { pathToFileURL } from "node:url";
import { safeErrorLabel } from "@gcpe/http-kit";
import { withAdmin } from "@gcpe/db-kit";

const HARNESS_DATABASES = [/^test_[0-9a-f]{20}$/, /^test_nr_[0-9a-f]{16}$/];
const HARNESS_ROLE = /^nr_[0-9a-f]{16}$/;
const DEFAULT_MIN_AGE_MINUTES = 60;

export const isHarnessDatabase = (name: string): boolean => HARNESS_DATABASES.some((re) => re.test(name));
export const isHarnessRole = (name: string): boolean => HARNESS_ROLE.test(name);

export interface Outcome {
  name: string;
  outcome: "dropped" | "would drop" | "skipped";
  reason?: string;
}
export interface CleanResult {
  databases: Outcome[];
  roles: Outcome[];
}
export interface CleanOptions {
  confirm: boolean;
  minAgeMinutes?: number;
  /** Narrows the run further (tests use it to stay off other suites' databases). Never widens it. */
  only?: (name: string) => boolean;
}

const codeOf = (e: unknown): unknown => (typeof e === "object" && e !== null ? (e as { code?: unknown }).code : undefined);

export async function cleanTestDbs(opts: CleanOptions): Promise<CleanResult> {
  const minAge = opts.minAgeMinutes ?? DEFAULT_MIN_AGE_MINUTES;
  const only = opts.only ?? (() => true);
  return withAdmin(async (c) => {
    const databases: Outcome[] = [];
    const names = (await c.query<{ datname: string }>("SELECT datname FROM pg_database WHERE NOT datistemplate ORDER BY datname")).rows
      .map((r) => r.datname)
      .filter((n) => isHarnessDatabase(n) && only(n));
    for (const name of names) {
      const { rows } = await c.query<{ sessions: number; age: number }>(
        `SELECT (SELECT count(*)::int FROM pg_stat_activity WHERE datname = $1) AS sessions,
                extract(epoch FROM now() - (pg_stat_file('base/' || oid || '/PG_VERSION')).modification)::float8 / 60 AS age
           FROM pg_database WHERE datname = $1`,
        [name],
      );
      const row = rows[0];
      if (!row) continue;
      if (row.sessions > 0) databases.push({ name, outcome: "skipped", reason: "in use" });
      else if (minAge > 0 && row.age < minAge) databases.push({ name, outcome: "skipped", reason: `created less than ${minAge} minutes ago` });
      else if (!opts.confirm) databases.push({ name, outcome: "would drop" });
      else {
        try {
          // `name` matched a harness pattern above: only [a-z0-9_], safe to quote.
          await c.query(`DROP DATABASE "${name}"`);
          databases.push({ name, outcome: "dropped" });
        } catch (e) {
          databases.push({ name, outcome: "skipped", reason: codeOf(e) === "55006" ? "in use" : safeErrorLabel(e) });
        }
      }
    }

    const roles: Outcome[] = [];
    const roleNames = (await c.query<{ rolname: string }>("SELECT rolname FROM pg_roles ORDER BY rolname")).rows
      .map((r) => r.rolname)
      .filter((n) => isHarnessRole(n) && only(n));
    for (const name of roleNames) {
      const twin = await c.query("SELECT 1 FROM pg_database WHERE datname = $1", [`test_${name}`]);
      const sessions = await c.query("SELECT 1 FROM pg_stat_activity WHERE usename = $1", [name]);
      if ((twin.rowCount ?? 0) > 0) roles.push({ name, outcome: "skipped", reason: "its database still exists" });
      else if ((sessions.rowCount ?? 0) > 0) roles.push({ name, outcome: "skipped", reason: "in use" });
      else if (!opts.confirm) roles.push({ name, outcome: "would drop" });
      else {
        try {
          await c.query(`DROP ROLE "${name}"`);
          roles.push({ name, outcome: "dropped" });
        } catch (e) {
          roles.push({ name, outcome: "skipped", reason: codeOf(e) === "2BP01" ? "still owns objects" : safeErrorLabel(e) });
        }
      }
    }
    return { databases, roles };
  });
}

function minAgeArg(argv: string[]): number | undefined {
  const arg = argv.find((a) => a.startsWith("--min-age-minutes="));
  if (!arg) return undefined;
  const n = Number(arg.slice("--min-age-minutes=".length));
  if (!Number.isInteger(n) || n < 0) throw new Error("--min-age-minutes takes a whole number of minutes");
  return n;
}

async function main(): Promise<void> {
  const argv = process.argv.slice(2);
  const confirm = argv.includes("--confirm");
  const r = await cleanTestDbs({ confirm, minAgeMinutes: minAgeArg(argv) });
  for (const [kind, list] of [["database", r.databases], ["role", r.roles]] as const) {
    for (const o of list) console.log(`${o.outcome.padEnd(10)} ${kind} ${o.name}${o.reason ? ` (${o.reason})` : ""}`);
  }
  const all = [...r.databases, ...r.roles];
  if (all.length === 0) console.log("No leftover test databases or roles.");
  else if (!confirm && all.some((o) => o.outcome === "would drop")) console.log("Dry run: nothing dropped. Re-run with --confirm to drop.");
}

if (pathToFileURL(realpathSync(process.argv[1]!)).href === import.meta.url) {
  main().catch((e) => {
    console.error(safeErrorLabel(e));
    process.exitCode = 1;
  });
}
```
